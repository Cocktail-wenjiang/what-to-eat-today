# 前端 UI 设计评审报告

> 评审对象：`frontend/`（「今天吃什么」用户端）
> 评审方式：Chrome 无头浏览器实测计算样式 + 多断点布局测量 + WCAG 2.1 对比度计算 + 源码复核
> 评审日期：2026-10-09

---

## 一、评审方法说明

本次评审不依赖主观印象，全部结论基于运行时实测数据：

| 检查项 | 方法 |
|---|---|
| 文字对比度 | 遍历 13 类文本元素，读取 `getComputedStyle().color`，逐级向上查找不透明背景，按 WCAG 2.1 相对亮度公式计算比值 |
| 字号层级 | 统计全部叶节点文本的 `font-size` 分布直方图 |
| 响应式 | 在 1440 / 1024 / 768 / 390 四个视口实测 `scrollWidth`、grid 列数、元素高度 |
| 触控目标 | 测量全部 `button`/`input` 的 `getBoundingClientRect()`，比照 44px 阈值 |
| 可访问性 | 检查 `aria-live` / `role` / `lang` / tabIndex 顺序 |
| 功能闭环 | 实际填表 → 提交 → 校验结果 → 触发降级通道 |

**测试数据**：3 人 / 40 分钟 / 高蛋白 / 忌花生 → 后端返回 2 条菜谱（正确排除「花生酱拌面」），通道显示「后端服务」，模式「规则放宽匹配」。

## 二、总体评价

### 做得好的部分（建议保留）

1. **视觉语言统一且有个辨识度**。墨绿 `#123b31` + 青柠 `#cdf561` 的搭配克制，Hero 区的轨道环 + 呼吸核心是有效的视觉锚点，不像模板化的「AI 生成感」。
2. **功能闭环完整**。三级降级链路（后端 / 云函数 / 云端直连）在界面上有明确反馈（通道徽标 + 状态条），加载态有骨架屏、空态区分「首访」与「无结果」、错误态有中文提示——这套状态设计已经超出课程作业平均水平。
3. **响应式无横向溢出**。四个断点实测 `scrollWidth ≤ innerWidth`，grid 列数按预期收敛（3→2→1），移动端 Hero 正确切换为 `display:block`。
4. **表单校验前后端一致**。前端 `validators.js` 与后端 pydantic 约束对齐，失焦即时反馈，且禁止在校验失败时提交。
5. **无障碍基础扎实**。`lang="zh-CN"` 正确、6 处 `aria-label`、`role="status"`、无缺失 alt 的图片、无纯图标按钮（均有文字或 aria-label）、22 个可聚焦元素 tabIndex 顺序合理。

## 三、问题清单（按严重度排序）

### P0 — 影响可读性，建议本轮修复

#### P0-1　六处文字对比度未达 WCAG AA

实测数据（目标 4.5:1）：

| 元素 | 字号 | 前景色 | 对比度 | 判定 |
|---|---|---|---|---|
| `.footer` | 10px | `#9aaba2` on `#f4f6f1` | **2.21:1** | ✗ 严重不足 |
| `.field-tip` | 10px | `#a2b0a8` on `#ffffff` | **2.26:1** | ✗ 严重不足 |
| `.section-kicker` | 11px | `#ff805b` on `#ffffff` | **2.47:1** | ✗ 严重不足 |
| `.history-mode` | 10px | `#81958b` on `#fbfcfa` | **3.09:1** | ✗ 不足 |
| `.status` | 12px | `#81958b` on `#ffffff` | **3.18:1** | ✗ 不足 |
| `.history-hint` | 10px | `#81958b` on `#ffffff` | **3.18:1** | ✗ 不足 |

对照达标的：`.channel-badge` 7.13:1、`.eyebrow` 9.93:1、`.history-time` 12.03:1。

**影响**：`.field-tip` 是表单的范围提示（「范围 1-20」），`.status` 是核心反馈文案，两者可读性不足会直接影响用户判断输入是否合法。

**改法**：把 `--muted` 从 `#81958b` 加深到 `#5c7267` 左右（对白底约 4.8:1），`.field-tip` 单独用 `#6b7d74`，`.footer` 用 `#7a8f85`。橙色 kicker 改为 `--ink-soft` 或加深到 `#c9553a`。

#### P0-2　字号体系失衡，13 档位中 10/11/12px 占 45%

实测分布：10px **29 处**、11px **17 处**、12px **33 处**，而承担正文的 16px 仅 **9 处**。

问题有三：
- **过于细碎**：11/12/13/14px 四档相邻，视觉上难以分辨，实际是「为了区分而区分」；
- **下限过低**：29 处 10px 文字在 1366×768 笔记本上已接近可读临界，且这些恰恰是「标签、时间、提示」等需要辨认的信息；
- **缺少正文层**：16px 只有 9 处，说明界面没有真正的「正文阅读区」，所有内容都被压成了注释级字号。

**改法**：收敛为 6 档 —— `11px`（仅装饰性全大写标签）/ `12px`（辅助信息）/ `13px`（正文与小标签）/ `16px`（正文与输入）/ `22px`（区块标题）/ `clamp()`（Hero）。把 10px 全部并入 12px，13/14px 合并为 13px。

### P1 — 影响易用性

#### P1-1　移动端三处触控目标不达标

实测（390px 视口）：

| 元素 | 尺寸 | 判定 |
|---|---|---|
| 「用这组条件」按钮 | 68 × **23px** | ✗ 严重偏小 |
| 顶栏刷新按钮 `⟳` | **26 × 26px** | ✗ 偏小 |
| 口味标签（清淡/高蛋白等） | 58 × **36px** | ⚠ 临界 |

其中「用这组条件」是最需要精确点击的元素，却只有 23px 高，手指误触率会明显偏高。

**改法**：历史重放按钮加 `padding: 8px 12px`（→ 约 36px）并改用 `position: static` + `margin-top` 布局，避免绝对定位压缩高度；刷新按钮加到 36px；口味标签在移动端提到 40px。

#### P1-2　`aria-live` 缺失，屏幕阅读器收不到结果反馈

实测 `aria-live` 数量为 **0**。推荐是异步操作，结果区变化时辅助技术完全无感知。`.status` 虽有 `role="status"`（隐式 `aria-live="polite"`，这项是对的），但结果列表容器没有。

**改法**：结果区加 `aria-live="polite"` 与 `aria-busy`，骨架屏已有 `aria-busy="true"` 但结果容器没有。

#### P1-3　历史面板默认全量渲染，10 条记录占 467px 页面高度

实测页面总高 1889px，其中历史面板 467px、占 24.7%。首屏用户要滚过 1300px 才看到历史，而这些记录大多是重复的演示数据。

**改法**：默认折叠为「最近 3 条 + 展开全部」，或做成横向滚动条带，把纵向空间还给主流程。

### P2 — 设计与一致性问题

#### P2-1　Hero 的「3 级数据降级」把架构细节当卖点

`hero-stats` 三项是「3 级数据降级 / 30min 最快上桌 / ∞ 菜谱可扩展」。第一项对用户毫无价值（用户不关心降级，只关心能不能出结果），第三项「∞」是空话。这是典型的「开发者视角泄漏到用户界面」。

**改法**：换成用户视角的真实数字，如「{n} 道可做菜谱 / 30 分钟最快上桌 / 支持忌口筛选」。

#### P2-2　区块标题全大写英文 + 中文双标题略显冗余

`YOUR INPUT / 告诉我你的需求`、`YOUR PICKS / 为你准备的菜单`、`RECIPE DETAIL`。英文 kicker 用 `letter-spacing:0.18em` 的全大写 11px，装饰性强但信息量为零，且 `.section-kicker` 正是对比度不达标（2.47:1）的元素之一。

**改法**：保留 kicker 但改为中文短标签或加深颜色；或只在 Hero 保留一次英文 kicker，内部区块去掉。

#### P2-3　`prefers-reduced-motion` 已有处理，但骨架屏 shimmer 未覆盖

`style.css` 末尾有 reduced-motion 规则批量关闭动画，骨架屏的 `@keyframes shimmer` 会被 `animation:none !important` 覆盖——**这项是正确的**。但 Hero 的 `.orbit-core` 呼吸动画也一并关闭后，圆环内会出现「静止但看得出是动画残留」的视觉空档，建议给 reduced-motion 下的 `.orbit-core` 一个静态高亮替代。

#### P2-4　详情弹窗缺少焦点陷阱（focus trap）

弹窗打开时会 `focus()` 到面板并锁定 body 滚动（这两点做得对），但没有焦点陷阱：用户按 Tab 会把焦点移到背后的表单元素上。对键盘用户是明显的破绽。

**改法**：在 `RecipeDetail.vue` 中拦截 Tab，把焦点循环限制在面板内的可聚焦元素之间。

## 四、优化方案

### 方案 A：快速修复（约 1 小时，建议本轮做）

只处理 P0 + P1，不动结构：

1. **调整设计令牌**（`style.css` 的 `:root`）
   ```css
   --muted: #5c7267;        /* 原 #81958b，对白底 ≥4.8:1 */
   --muted-strong: #46584f; /* 用于需要更清晰的小字 */
   ```
   同步替换硬编码的 `#a2b0a8`、`#9aaba2`、`#81958b`。

2. **重建字号阶梯**，定义 6 个 token 并替换全站零散写死的 px：
   ```css
   --fs-micro: 11px;   /* 仅全大写装饰标签 */
   --fs-xs: 12px;      /* 时间、标签、辅助提示 */
   --fs-sm: 13px;      /* 正文、小标签 */
   --fs-base: 16px;    /* 输入、正文 */
   --fs-lg: 22px;      /* 区块标题 */
   ```
   10px → 12px（29 处），11px → 12px 或 11px（按用途），13/14px → 13px。

3. **触控目标**：历史重放按钮 `padding` 提到 `8px 12px`；刷新按钮 26→36px；口味标签移动端 36→40px。

4. **补 `aria-live`**：结果容器加 `aria-live="polite"`。

5. **Hero 文案**替换为真实数据。

### 方案 B：体验增强（约 3-4 小时，可选）

在方案 A 基础上：

6. **结果区加筛选/排序**：按用时、按标签筛选，让「3 条推荐」变成「可浏览的菜谱库」。
7. **历史面板改折叠式**：默认 3 条，展开看全部，省 300px+ 纵向空间。
8. **详情弹窗焦点陷阱** + `aria-labelledby` 关联标题。
9. **推荐卡片加视觉分层**：当前三张卡片仅靠顶部 4px 色条区分（橙/蓝/绿），信息层级偏平。可给第一条（最佳匹配）加轻微强调。
10. **空态给出可操作建议**：当前「减少条件后重试」已有按钮，可再列出「当前条件命中了 0 条，去掉『素食』有 3 条」。

### 方案 C：视觉升级（需要设计稿，不推荐本学期做）

重做信息架构与视觉系统（配色扩展、插图、动效体系）。课程周期内性价比低，且当前视觉已达到「干净可用」标准。

### 7.2 交付内容

**P0 修复**
- 重建设计令牌：`--ink/-soft/-muted/-muted-soft/-muted-faint`、`--orange-ink #b8481f`、`--danger #b03f24`，全部按 4.5:1 反算。
- 字号体系收敛为 `--fs-micro/xs/sm/base/lg/xl`（11/12/13/16/22/25px），移除全部 10px 与 `text-transform: uppercase`。
- 触控目标：口味标签 40→44px（移动端）、历史重放按钮 23→34px（移动端 44px）、弹窗关闭按钮 40px（移动端 44px）、刷新按钮补齐。

**P1 无障碍**
- 结果区 `aria-live="polite"` + `:aria-busy`，加载态可被读屏播报。
- 详情弹窗：`aria-labelledby="detail-title"`、Tab 焦点陷阱、`body` 滚动锁定、`Esc` 关闭。

**P2 体验增强**
- **结果区筛选 + 排序**：按标签筛选、按匹配度/用时升降序；无筛选结果时给出「清除筛选」。
- **历史折叠**：默认展示 3 条，`aria-expanded` 可展开全部。
- **空态可操作建议**：当无结果时，计算「放宽某条件后能命中多少条」并给出可点击按钮，点击即应用补丁重试。
- **Hero 文案改写**：从开发者的「3 级数据降级」改为用户可见的「N 道可做菜谱」。

### 7.3 复测过程中发现并修复的真实缺陷

1. **建议计数被兜底逻辑掩盖**
   初版用 `recommendByRules` 统计放宽后的命中数，但它内含「软条件无命中就放开口味」的兜底，导致「口味改不限」这类建议的增量被吞掉（如素食+3min 只出 1 条）。
   **修复**：新增 `countStrictMatches()`，严格判定、不触发兜底；并增加「用时放宽 + 口味不限」组合候选，按命中数降序去重取前 3。

2. **菜谱池加载失败时建议功能静默失效**（严重）
   `ensureRecipePool()` 在 Supabase 已配置但不可达时**没有任何本地兜底**，`recipePool` 恒为空 → `suggestions` 恒为 `[]` → 空态退化成无效的「放宽条件重新推荐」按钮，Hero 菜谱数也停在占位符。
   **修复**：改为「Supabase → 本地种子 `public/data/recipes.json`」两级加载。

3. **Supabase 请求无超时导致兜底永不触发**
   上述修复后仍失效，根因是 `fetchRecipes()` 离线时**挂起而不抛错**，`await` 永远等不到，`catch` 分支永不执行。
   **修复**：为 `fetchRecipes()` 增加 `withTimeout()`（默认 6s），超时即抛错并落到本地种子。
